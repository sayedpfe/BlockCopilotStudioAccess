Copilot Studio Access Lockdown

Two scripts. Run one once for the tenant, run the other per user.

Contents

TL;DR 1. Objective 2. The three layers of defense 3. Access decision flow 4. The two scripts 5. One-time: configure the tenant 6. Per user: grant access 7. Revoke access 8. Full rollback 9. Verification checklist

TL;DR

  1. Run Configure-Tenant-CopilotStudioLockdown.ps1 once.
  2. For every user who needs Copilot Studio: run .\Grant-CopilotStudioAccess.ps1 -Upn user@tenant.
  3. To revoke: remove them from the Copilot Studio Authors group.
M365 Copilot license already includes the entitlement; the group controls who can sign in.

1. Objective

Restrict Copilot Studio (web portal + agent creation) to only members of the Copilot Studio Authors Entra group. Prevent everyone else from creating Dataverse-for-Teams environments.

Microsoft documents that no single tenant setting blocks Dataverse-for-Teams environment creation. Multiple surfaces can trigger it (Teams app, Copilot Studio web, Power Apps maker portal, viral trial signup). This runbook closes all four doors.

2. The three layers of defense

All three are applied automatically by the one tenant configuration script.

Layer 1 Entra portal lock

Sets AppRoleAssignmentRequired=True on Power Virtual Agents + Microsoft Copilot Studio Service enterprise apps; assigns the Authors group. Anyone outside the group is rejected at sign-in.

Layer 2 Block self-service trials

Remove-AllowedConsentPlans Internal,Viral — stops users from acquiring the Copilot Studio Viral Trial SKU that would bypass the group.

Layer 3 Power Platform tenant flags

Disables non-admin creation of production / trial / developer environments from make.powerapps.com.

4. The two scripts

FileWhen to runWhat it does
Configure-Tenant-CopilotStudioLockdown.ps1Once, at initial setupApplies all 3 defense layers. Idempotent — safe to re-run.
Grant-CopilotStudioAccess.ps1Each time you onboard a userAdds the user to the Copilot Studio Authors group.

5. One-time: configure the tenant

Prerequisites

  • PowerShell 7+ (pwsh)
  • Roles: Power Platform Administrator + Global Administrator
  • An Entra group named Copilot Studio Authors. Edit $AuthorsGroupName at the top of the script if your group has a different name.

Run it

.\Configure-Tenant-CopilotStudioLockdown.ps1
The script is idempotent — re-running it has no side effects.

6. Per user: grant access

Prerequisite

The user has a license that includes Copilot Studio entitlement (e.g. Microsoft 365 Copilot).

Run it

.\Grant-CopilotStudioAccess.ps1 -Upn alice@M365CPI90282478.onmicrosoft.com

Bulk add

'alice@tenant.com','bob@tenant.com' |
    ForEach-Object { .\Grant-CopilotStudioAccess.ps1 -Upn $_ }

7. Revoke access

Connect-MgGraph -NoWelcome -Scopes "Group.ReadWrite.All","User.Read.All"
$g = Get-MgGroup -Filter "displayName eq 'Copilot Studio Authors'"
$u = Get-MgUser  -UserId 'alice@M365CPI90282478.onmicrosoft.com'
Remove-MgGroupMemberByRef -GroupId $g.Id -DirectoryObjectId $u.Id

8. Full rollback

Re-allow Copilot Studio portal for everyone

Connect-MgGraph -NoWelcome -Scopes "Application.ReadWrite.All"
$sps = '96ff4394-9197-43aa-b393-6a41652e21f8','9d8f559b-5984-46a4-902a-ad4271e83efa'
foreach ($appId in $sps) {
    $sp = Get-MgServicePrincipal -Filter "appId eq '$appId'"
    Update-MgServicePrincipal -ServicePrincipalId $sp.Id -AppRoleAssignmentRequired:$false
}

Re-allow viral / internal trial signups

Add-AllowedConsentPlans -Types @('Internal','Viral')

Re-enable non-admin environment creation

$body = [pscustomobject]@{
    disableEnvironmentCreationByNonAdminUsers      = $false
    disableTrialEnvironmentCreationByNonAdminUsers = $false
    powerPlatform = [pscustomobject]@{
        governance = [pscustomobject]@{
            disableDeveloperEnvironmentCreationByNonAdminUsers = $false
        }
    }
}
Set-TenantSettings -RequestBody $body
